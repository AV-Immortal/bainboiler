# BAIN BOILER 官网设计方案

## 1. 项目概述

本项目为中国境内锅炉企业“上海百恩锅炉有限公司”建设一个面向中国境内与境外客户的双语企业官网，品牌域名标识暂按 `bainboiler` 规划。网站部署在香港服务器，目标是兼顾国际化品牌形象、工业企业可信度、海外 SEO、国内外客户询盘转化以及后续非技术人员可维护性。

视觉与布局方向参考 `https://www.babcock.com`，但不做逐像素复制。整体设计风格确定为“国际重工企业感”，首页结构采用“品牌大图型”，并以首屏背景视频强化高端、稳重、可信的工业集团气质。

## 2. 目标与范围

### 2.1 目标

- 建立一个具有国际工业品牌气质的高端企业官网。
- 同时服务中文与英文访客，并支持自动识别与手动切换语言。
- 让非技术人员可在后台快速维护中英文内容、图片、视频、产品、案例、新闻和 SEO。
- 支持官网展示、产品了解、资料下载、直接联系和询盘转化。
- 为后续新增页面、语言、地区落地页和更多营销能力保留扩展空间。

### 2.2 首期范围

- 企业官网前端站点
- 中英文双语系统
- Headless CMS 内容管理后台
- 首页背景视频与视频中心
- 产品、解决方案、案例、新闻、下载、联系与询盘能力
- SEO 基础设施
- 香港服务器部署方案

### 2.3 非目标

- 首期不建设 ERP、CRM、订单、支付、会员、经销商后台等复杂业务系统。
- 首期不建设多语言超过中文和英文之外的语种。
- 首期不做复杂在线选型引擎或实时客服系统。

## 3. 推荐方案

### 3.1 方案比较

#### 方案 A：纯定制前端 + 纯定制后台

优点：

- 灵活度最高
- 所有内容模型都可完全按业务定制

缺点：

- 开发成本高
- 后台建设周期长
- 非技术人员的编辑体验不一定优于成熟 CMS

#### 方案 B：纯 CMS 模板站

优点：

- 上线快
- 后台编辑体验通常较成熟

缺点：

- 难以实现高端工业集团官网的品牌感
- 模板约束明显
- 不利于构建清晰的可替换前端模块体系

#### 方案 C：定制前端 + Headless CMS + 模块化配置

优点：

- 前端可实现接近国际工业集团官网的高级视觉与交互
- 非技术人员可通过 CMS 维护中英文内容与媒体资源
- 前端每个 UI 模块可单独文件夹拆分，便于后续替换与扩展
- 兼顾品牌展示、SEO、性能和转化

缺点：

- 技术实现复杂度高于模板站
- 需要建立前后端内容映射规范

### 3.2 推荐结论

推荐采用“定制前端 + Headless CMS + 模块化配置”方案。

该方案最符合本项目的核心诉求：

- 视觉上接近 `babcock.com` 的国际重工品牌感
- 中英文独立内容管理
- 非技术人员可快速替换内容
- 前端模块边界清晰，后续方便改版和扩展

## 4. 技术架构

### 4.1 前端

前端建议使用 `Next.js`。

原因：

- 适合企业官网和 SEO
- 适合多语言路由
- 适合媒体内容、首屏视频和模块化页面拼装
- 适合后续扩展更多语言、地区页和营销落地页

### 4.2 内容管理后台

后台建议优先使用 `Strapi`，备选为 `Directus`。

推荐 `Strapi` 的原因：

- 更适合内容驱动型官网
- 可灵活定义内容模型
- 媒体管理、关系管理和 API 输出较成熟
- 非技术编辑更容易理解页面与内容结构

### 4.3 部署形态

- 官网前端：部署于香港服务器
- CMS 后台/API：部署于香港服务器，建议独立子域名
- 媒体资源：建议走对象存储或静态资源服务
- CDN：按预算与访问情况决定是否补充

推荐域名形态：

- 官网：`www.bainboiler.com` 或最终正式主域名
- CMS：`cms.bainboiler.com`
- 媒体：可单独放静态资源域名

## 5. 视觉与品牌方向

### 5.1 视觉方向

视觉方向确定为“国际重工企业感”。

核心特征：

- 深蓝、灰、白为主色
- 大幅工业场景或工厂环境视觉
- 强调沉稳、权威、可信和工程能力
- 信息密度克制，版式整洁，有明显留白和大图节奏

### 5.2 首页结构方向

首页采用“品牌大图型”。

核心特征：

- 首屏以大图或视频建立品牌气场
- 通过简洁但有力量的文案传递企业定位
- 后续逐层展开实力、产品、解决方案、案例和转化信息

### 5.3 视频方向

首页首屏采用背景视频。

原则：

- 自动播放
- 静音
- 循环
- 配合封面海报图
- 移动端和弱网场景允许降级为静态封面图

## 9. 双语与国际化设计

### 9.1 路由结构

建议采用：

- 中文：`/zh`
- 英文：`/en`

页面统一放在带语言前缀的结构下，便于 SEO 和扩展。

### 9.2 自动切换逻辑

首次访问时，按以下优先级决定语言：

1. 用户是否已有手动切换记录
2. 浏览器语言
3. 访问地区

保守规则：

- 中国大陆访问默认中文
- 其他地区默认英文

### 9.3 手动切换逻辑

- 顶部导航和移动端菜单始终提供 `中文 | EN` 切换
- 用户手动切换后写入 cookie
- 后续优先尊重用户手动选择

### 9.4 SEO 规则

每个语言版本都应有独立的：

- URL
- `title`
- `description`
- `open graph`
- `hreflang`

## 11. 非技术人员可维护性设计

后台字段命名应尽量业务化，不要求编辑人员理解代码概念。

示例字段命名：

- 首页主标题中文
- 首页主标题英文
- 首屏背景视频
- 首页按钮文字
- 首页按钮链接
- 是否显示此模块

维护原则：

- 图片、视频、PDF 通过媒体库统一管理
- 模块支持显隐和排序
- 中英文内容独立维护
- 尽量避免暴露 JSON 或复杂技术字段

## 12. 前端模块化规范

建议目录结构如下：

```text
src/
  app/
    [locale]/
  modules/
    hero-video/
    brand-stats/
    company-intro/
    product-categories/
    industry-solutions/
    project-showcase/
    certificates-export/
    featured-video/
    latest-news/
    contact-cta/
  components/
  lib/
  services/
  types/
  i18n/
```

每个模块目录建议包含：

- `index.tsx`
- `types.ts`
- `mapper.ts`
- `README.md`
- `components/`
- `styles/`

### 12.1 模块边界

- 模块只负责自己的展示逻辑
- 页面层只负责组装模块
- CMS 数据先经过映射层再交给 UI

### 12.2 模块 README 规范

每个模块的 `README.md` 至少说明：

- 模块显示在哪个页面
- 模块作用是什么
- CMS 对应字段有哪些
- 要替换该模块时应修改哪个目录

## 13. 性能策略

### 13.1 视频策略

- 首屏视频采用压缩后的 `MP4/WebM`
- 配套海报图
- 自动播放、静音、循环
- 移动端必要时降级为封面图

### 13.2 图片策略

- 使用压缩图
- 提供不同尺寸
- 优先保证首屏加载体验

### 13.3 内容加载策略

- 首屏关键文案先展示
- 大媒体资源延迟或分级加载
- 不让视频成为首屏唯一信息承载方式

## 14. SEO 与转化策略

### 14.1 SEO

- 中英文独立 URL
- 产品页、解决方案页、案例页均应具备独立详情页
- 每页独立 SEO 字段
- 规范化 `hreflang`

### 14.2 询盘转化

必须同时提供三类转化路径：

- 提交询盘
- 直接联系销售
- 浏览产品和资料后再转化

建议表单字段：

- 姓名
- 邮箱或电话
- 国家
- 锅炉类型
- 需求描述

## 15. 部署与运维

### 15.1 部署建议

- 前端与 CMS 分开部署
- CMS 使用独立子域名
- 配置 HTTPS
- 做基础备份
- 做错误日志与访问监控

### 15.2 安全与稳定性

- 表单反垃圾
- 基础限流
- 后台访问控制
- 媒体与备份策略

### 15.3 后续扩展空间

后续可扩展：

- 更多语言版本
- 更多地区落地页
- 广告转化跟踪
- 更细的产品筛选和营销页

## 16. 实施建议

建议按以下顺序推进：

1. 确认正式品牌资料、企业资料、产品目录和视频素材
2. 搭建前端项目骨架与 CMS 基础内容模型
3. 实现首页与核心页面模板
4. 接入双语、SEO 和表单
5. 录入首批中英文内容
6. 联调、性能优化和上线

## 17. 结论

本项目最适合采用“Next.js 定制前端 + Strapi Headless CMS + 模块化内容配置”的建设方式。

这样既能实现接近国际工业集团官网的高级视觉表达，又能让非技术人员在后台快速维护中英文内容，并且通过清晰的模块边界保障后续任意页面和模块的替换能力。
